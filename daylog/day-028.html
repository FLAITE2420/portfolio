Concept #28 — The route everyone picks is not the route that is fastest for everyone

MA07, Operations Research, routing. The course notes say it in one line: individually

rational routing is not system optimal. I had read that as a remark about traffic jams.

It is a theorem with a number attached, and the number is 4/3.

The instance is small enough to hold in my head. A hundred drivers, two roads between

the same two points. Road A costs 1.0 no matter what. Road B costs the share of the

fleet that is on it, so if all hundred take it, each of them pays 1.0. Every driver

compares their own two numbers and takes the cheaper road. The equilibrium is not

50/50: it is 99 or 100 on road B — the whole fleet — at 1.0000 per driver. The

system optimum is 50/50 at 0.7500. The equilibrium is 1.333333 times the

optimum, and 1.333333 is 4/3 exactly, to six decimals.

That is the whole mechanism in one line: a driver on the shared road pays their own

share of the congestion and nothing for the congestion they add to everyone behind

them. Each comparison is correct. The aggregate is not. I also ran the same network at

N = 2, 3, 4, 6, 10 and 12 drivers, and the ratio sits on 4/3 every time except N = 3,

where the granularity of three whole drivers cannot split evenly and it lands on

1.2857. So the 4/3 is a property of the network, not of the fleet size I happened to

pick.

Then the part that made me put the pen down. Take a network with four roads where the

selfish equilibrium is already optimal — 3 drivers one way, 3 the other, 9.000 total,

1.5000 each, and my enumeration confirms equilibrium equals optimum. Now build one

more road between the midpoints, and make it free. I enumerated all 84 ways to

distribute 6 drivers over the 4 possible routes and tested every single driver's every

alternative — 167 single-driver moves. Five of the 84 distributions are equilibria.

One of them is "everyone on the new shortcut": each pays 2.0000, total 12.000.

It is a real equilibrium — a defecting driver pays exactly 2.0000 on either old route,

thanks to the tie, so nobody improves. The old network's cost was 9.000, and the best

achievable cost with the new road is still 9.000 (3 on one shortcut route, 3 on the

other, which is what the optimum always was). The road added capacity, changed nothing

about what is possible, and moved the worst equilibrium up by 33.33%.

I want to be honest about one thing, because the reproduction is not quite the

textbook: the cheapest equilibrium is 10.333, not 12.000. There are five equilibria

and the fleet can land on any of them. The finding is not "the road always costs

everyone 33% more" — it is "the road created equilibria that are worse than the single

equilibrium the network had before, and the textbook one is among them". With a small

fleet and one-driver moves, ties are everywhere; that is the honest shape of the

result.

What I tried today: one file, stdlib only, no solver. Exact enumeration of

equilibria (every driver's every alternative tested, not sampled), exact enumeration of

optima, and the same arithmetic across fleet sizes so the 4/3 is not a coincidence of

N = 100.

# selfish_routing.py - MA07 (Operations Research): congestion games.
# Source: the course notes on routing models ("individually rational routing is
# not the same as system optimal"), plus the Pigou / Braess instances.
#
# stdlib only, no solver library. Everything below is exact enumeration:
#   1. Pigou's two-road instance, N=100 drivers, discrete. Find every flow in
#      which no single driver can improve by switching, then the system
#      optimum, then the ratio (the price of anarchy).
#   2. The same measurement at every N from 2 to 12, to see whether the ratio
#      is an artifact of N.
#   3. Braess: the four-road network, N=6, with and without a zero-cost
#      shortcut. Enumerate all C(N+3,3) distributions, test every driver's
#      every alternative, and compare the equilibrium cost with the network
#      that has one road fewer.
#
# Latency is "minutes" as a fraction of the fleet, so a road carrying the whole
# fleet one way costs 1.0 for the driver on it. Nothing here is random.

N = 100          # drivers
TOTAL = 1.0

# ---------------------------------------------------------------- 1. Pigou
# Link A: latency 1.0, no matter how many drivers. Link B: latency = share.
def pigou_cost(k):
    """Total minutes for the fleet when k drivers use link B."""
    return k * (k / N) + (N - k) * 1.0

def pigou_nash():
    """Every k where no single driver can lower their own time by moving."""
    out = []
    for k in range(N + 1):
        # a driver on B pays k/N; moving to A costs 1.0 (and the fleet becomes
        # T+1 on A: irrelevant, A's latency is constant)
        b_ok = (k == 0) or (k / N <= 1.0)
        # a driver on A pays 1.0; moving to B costs (k+1)/N
        a_ok = (k == N) or (1.0 <= (k + 1) / N)
        if b_ok and a_ok:
            out.append(k)
    return out

nash = pigou_nash()
best_k = min(range(N + 1), key=pigou_cost)
print("== 1. Pigou: one free-flow road (1.0) and one road that costs its own share")
print(f"drivers N = {N}")
print("equilibrium flows (k on the congestible road):", nash,
      "-> per-driver time", [round(min(k, N) / N, 4) if k else 1.0 for k in nash])
for k in nash:
    print(f"  k={k:3d}: total={pigou_cost(k):8.3f}  per driver={pigou_cost(k)/N:.4f}")
print(f"system optimum: k={best_k} total={pigou_cost(best_k):.3f} "
      f"per driver={pigou_cost(best_k)/N:.4f}")
worst = max(pigou_cost(k) for k in nash)
print(f"price of anarchy (worst equilibrium / optimum) = "
      f"{worst / pigou_cost(best_k):.6f}")
# the exact algebra, to check the enumeration is not off by a rounding
print(f"branded value 4/3 = {4/3:.6f}")
print()

# --------------------------------------------------- 2. is it the fleet size?
print("== 2. the ratio at other fleet sizes (same network, recomputed)")
for n in (2, 3, 4, 6, 10, 12):
    def cost(k, n=n):
        return k * (k / n) + (n - k) * 1.0
    ks = [k for k in range(n + 1)
          if (k == 0 or k / n <= 1.0) and (k == n or 1.0 <= (k + 1) / n)]
    opt = min(range(n + 1), key=cost)
    w = max(cost(k) for k in ks)
    print(f"  N={n:3d}  nash flows={ks}  worst={w:7.3f}  opt={cost(opt):7.3f}  "
          f"ratio={w / cost(opt):.4f}")
print()

# ------------------------------------------------------------- 3. Braess
# Roads: S->A (share), A->T (1.0), S->B (1.0), B->T (share).
# Paths without the shortcut: SAT, SBT.  With it: SAT, SBT, SABT, SBAT.
M = 6

def no_shortcut_cost(a, m=M):
    b = m - a
    return a * (a / m + 1.0) + b * (1.0 + b / m)

def no_shortcut_nash(m=M):
    out = []
    for a in range(m + 1):
        b = m - a
        # driver on SAT pays a/m + 1, moving to SBT would cost 1 + (b+1)/m
        ok_sat = (a == 0) or (a / m + 1.0 <= 1.0 + (b + 1) / m)
        ok_sbt = (b == 0) or (1.0 + b / m <= (a + 1) / m + 1.0)
        if ok_sat and ok_sbt:
            out.append(a)
    return out

def with_shortcut_cost(f):
    """f = (sat, sbt, sabt, sbat); latency = flow-on-that-edge / M."""
    sat, sbt, sabt, sbat = f
    f_sa = sat + sabt          # S->A carries both paths that start on it
    f_bt = sbt + sabt          # B->T carries both paths that end on it
    return (sat * (f_sa / M + 1.0)
            + sbt * (1.0 + f_bt / M)
            + sabt * (f_sa / M + f_bt / M)
            + sbat * 2.0)      # S->B + A->B(0) + A->T

def compositions(total, parts):
    if parts == 1:
        yield (total,)
        return
    for first in range(total + 1):
        for rest in compositions(total - first, parts - 1):
            yield (first,) + rest

PATHS = ["S-A-T", "S-B-T", "S-A-B-T", "S-B-A-T"]

def path_cost(f, i, m=M):
    """Time paid by a driver choosing path i, given the full flow vector f
    (that driver included)."""
    sat, sbt, sabt, sbat = f
    f_sa = sat + sabt          # S->A carries both paths that start on it
    f_bt = sbt + sabt          # B->T carries both paths that end on it
    if i == 0:      # S-A-T
        return f_sa / m + 1.0
    if i == 1:      # S-B-T
        return 1.0 + f_bt / m
    if i == 2:      # S-A-B-T (shortcut is free)
        return f_sa / m + f_bt / m
    return 2.0      # S-B-A-T: 1.0 + 0 + 1.0

def with_shortcut_nash(m=M):
    """All distributions where no driver can improve by moving one unit."""
    nash, checks = [], 0
    for f in compositions(m, 4):
        ok = True
        for i in range(4):
            if f[i] == 0:
                continue
            mine = path_cost(f, i)
            for j in range(4):
                if j == i:
                    continue
                checks += 1
                h = list(f); h[i] -= 1; h[j] += 1
                if path_cost(h, j) < mine - 1e-12:
                    ok = False
                    break
            if not ok:
                break
        if ok:
            nash.append((f, with_shortcut_cost(f)))
    return nash, checks

print(f"== 3. Braess with {M} drivers")
a_nash = no_shortcut_nash()
print("without the shortcut:")
for a in a_nash:
    print(f"  split SAT={a} SBT={M-a}: total={no_shortcut_cost(a):.3f} "
          f"per driver={no_shortcut_cost(a)/M:.4f}")
no_opt = min(range(M + 1), key=no_shortcut_cost)
print(f"  optimum: SAT={no_opt} total={no_shortcut_cost(no_opt):.3f}")
print(f"  equilibrium == optimum: "
      f"{all(abs(no_shortcut_cost(a) - no_shortcut_cost(no_opt)) < 1e-12 for a in a_nash)}")

bn, checks = with_shortcut_nash()
print(f"with the free shortcut A->B (every distribution enumerated, "
      f"{checks} single-driver moves tested):")
best = min(bn, key=lambda t: t[1])
worst = max(bn, key=lambda t: t[1])
for f, c in bn:
    print(f"  {dict(zip(PATHS, f))}: total={c:.3f} per driver={c/M:.4f}")
print(f"  {len(bn)} of {len(list(compositions(M, 4)))} distributions are equilibria")
print(f"  cheapest equilibrium: total={best[1]:.3f}")
print(f"  the extra road costs the fleet "
      f"{best[1] - no_shortcut_cost(no_opt):.3f} minutes more, "
      f"and every driver is still doing the best they can")
print(f"  per driver: {no_shortcut_cost(no_opt)/M:.4f} without -> "
      f"{best[1]/M:.4f} with (ratio {best[1] / no_shortcut_cost(no_opt):.6f})")
print(f"  worst equilibrium (everyone on the shortcut): "
      f"total={worst[1]:.3f} per driver={worst[1]/M:.4f} "
      f"-> ratio {worst[1] / no_shortcut_cost(no_opt):.6f}")

print()
print("== 4. what the extra road actually bought")
all_flows = [(with_shortcut_cost(f), f) for f in compositions(M, 4)]
opt_with, opt_flow = min(all_flows)
print(f"best possible total, with the shortcut: {opt_with:.3f} "
      f"at {dict(zip(PATHS, opt_flow))}")
print(f"best possible total, without it:        {no_shortcut_cost(no_opt):.3f}")
print(f"so the road did not improve the optimum at all: "
      f"{abs(opt_with - no_shortcut_cost(no_opt)) < 1e-12}")
print(f"and the worst equilibrium went from {no_shortcut_cost(no_opt):.3f} "
      f"to {worst[1]:.3f} (+{100*(worst[1]/no_shortcut_cost(no_opt)-1):.2f}%)")

What I understood from it: an equilibrium condition is local by construction —

each agent only compares their own cost — so it cannot see the aggregate, and that is

not a bug in the agent, it is what "selfish" means. Capacity added where the flow

already is lowers the marginal cost of a route, which attracts flow until the

congestion returns, and the route that was supposed to relieve the load becomes the

load. Any system that lets each request pick the replica that currently looks fastest

has this exact shape: the fastest-looking replica is the one with the shortest queue,

so every request goes there, and the load balancer manufactures the queue it was

supposed to remove. The number to watch is the total, not the per-request time — and

the per-request number is precisely the one that looks fine at the equilibrium.

Security #28 — The validator normalized, and NFKC does not touch what the attacker used (CWE-176)

I picked this because it is the one class where the defensive code looks careful.

The input gets normalized, then compared to a blocklist, then lowercased. Three steps.

The bug is not a missing step, it is a wrong belief about what one of them does.

NFKC normalizes compatibility: fullwidth letters, ligatures, no-break spaces. It

does not normalize confusables — different characters that render the same

glyph. That is a different problem with a different data file (UTS #39), and it is not

in the standard library.

Measured on eight candidates for the name admin:

  • fullwidth ａｄｍｉｎ → NFKC folds it to admin → blocked. The step works.
  • Cyrillic а аdmin (U+0430, not U+0061) → NFKC leaves it alone, length 5, prints

as admin in every font I have → passes.

  • zero-width space admin\u200b → length 6, and strip() does not touch it,

because U+200B is not whitespace in Python → passes. It is a distinct string that

a moderator reads as admin.

  • dotted capital I ADMİN → .lower() gives admi̇n, six codepoints, not five.

Turkish dotted I does not lowercase to a plain i, so a blocklist written in ASCII

never matches a name typed on a Turkish keyboard.

  • dotless i admın → passes for the same reason, mirrored.
  • no-break space admin + U+00A0 → NFKC turns it into a space and strip() eats

it → blocked. This one is caught by accident: the normalizer and the stripper

happened to agree.

  • ligature ﬁ → 3 codepoints become 4. NFKC changes the length of the string, so

a max-length check done before normalization is validating a different string than

the one that gets stored.

Then the filesystem. I created a file named with U+202E RIGHT-TO-LEFT OVERRIDE in the

middle: quarterly\u202etxt.exe. The real extension is .exe; endswith(".pdf") is

False; on screen the override reverses the run after it and the eye reads

quarterlyexe.txt. One string for the validator, another for the human, and the OS

executes the one the validator read.

Then the database, which is where this stops being cosmetic. With canon unique:

  • fullwidth twin → IntegrityError. Good: one canonical key, one row.
  • Cyrillic twin → inserts. Zero-width twin → inserts. Three rows, two of which

a human reads as admin.

So the unique index on the normalized form does half the job — it stops one class of

duplicate and allows the class that is actually being used for impersonation. If the

canonical form is the join key, the lookalike sits in the table as a normal user, and

every surface that renders names — moderation, reports, logs, the admin panel — shows

it as admin. The database is right. The display is a lie it never agreed to tell.

And the same codepoint boundary in authentication: the password café typed composed

is 4 codepoints / 5 bytes and hashes to 850f7dc43910ff89; typed decomposed it is 5

codepoints / 6 bytes and hashes to 81ef060bcd98adc7. Two keyboards, two hashes, one

user who swears they typed the same password.

The pattern I studied — the defense as usually written, and the two lines that

break it:

key = unicodedata.normalize("NFKC", name).strip().lower()
if key in BLOCKED: reject()
# Cyrillic "а" survives: len 5, looks identical, is not in BLOCKED
# "admin\u200b" survives: strip() is documented on whitespace, U+200B is not that

What I understood about preventing it:

import unicodedata as ud

def canon(s):                      # one form, computed once, at the edge
    return ud.normalize("NFKC", s).casefold()

def has_hidden(s):                 # bidi controls and default-ignorables are not
    return any(ud.category(ch) in ("Cf", "Cc") for ch in s)

# store canon(), compare canon() only — never raw vs canonical
# reject has_hidden() outright: no legitimate display name needs a zero-width joiner
# confusables need their own map (UTS #39), because NFKC will never fold а -> a
# hash the canonical form of the password, not the bytes the keyboard produced

The two rules that survive every case above: **canonicalize exactly once, at the

boundary, and store only the canonical form** (so the unique index and the login

comparison are looking at the same string), and **reject invisible and bidi

characters** — they hide characters, they do not name them. Confusables are a third

problem and the fix is not normalization; it is a confusables skeleton or an explicit

script allowlist per field, and I have not implemented that yet.

#      validator sees versus the extension the OS executes

#      database does with them

== 5. the same password, hashed twice
  composed (NFC)   len=4 bytes= 5 sha256[:16]=850f7dc43910ff89
  decomposed (NFD) len=5 bytes= 6 sha256[:16]=81ef060bcd98adc7
  looks identical in any font, is a different password unless the
  application normalizes before hashing.

What I understood: normalization answers "are these the same character". It does

not answer "does this look like that character" — and impersonation is the second

question. The dangerous version of this bug is not the one that crashes; it is the one

that passes review because the diff shows normalize in it. A defensive step that

looks right and covers one of three cases is worse than no step at all, because it ends

the conversation.
