Concept #34 — A pruner that keeps everything, and the graph shape that makes it complete

MA08, Intelligent Search, week 5. Week 4 built the model: variables, domains, constraints, and

depth-first assignment over them. Week 5 asks what can be taken out of the search before it

starts. The slides name three levers: prune the domains, repair a complete assignment, exploit the

shape of the constraint graph.

The pruning lever is the one that gets treated as a certificate. REVISE(X, Y) deletes every value

of X that has no compatible value in Y. AC-3 puts all arcs in a queue, revises them, and re-enqueues

the neighbours of any variable whose domain shrank, until the queue empties or a domain does. If it

ends with every domain non-empty, the CSP is arc-consistent. That is the entire guarantee.

Arc-consistent is not satisfiable — the slides say it twice, in two different places — so I built the

smallest set of instances where I could count the gap by brute force.

All four use one constraint (two neighbours must differ), so what changes between rows is the graph,

not the constraint language.

What I tried today: one file, stdlib only, no network. A generic AC-3 over a queue, a

backtracking solver with three inference modes, a tree solver that never searches, and min-conflicts

with and without the escape move. Four small instances I could enumerate exhaustively, one

unsatisfiable tree, and one 12-node tree.

"""Day 34 concept: what arc consistency proves, and what a tree lets you skip.

One file, stdlib only, no network. Every number printed below came from this run.
Every constraint here is the same one -- two neighbours must differ -- so what
changes between the instances is structure, never the constraint language.

import random
from collections import deque


class CSP:
    def __init__(self, variables, domains, edges):
        self.vars = list(variables)
        self.dom0 = {v: list(domains[v]) for v in self.vars}
        self.nb = {v: [] for v in self.vars}
        for a, b in edges:
            self.nb[a].append(b)
            self.nb[b].append(a)

    def ok(self, a, x, b, y):
        return x != y          # "different value" is the whole constraint language today


def php(pigeons, holes):
    """Pigeonhole: any two pigeons need different holes. Complete graph."""
    vs = ["p%d" % i for i in range(pigeons)]
    edges = [(a, b) for i, a in enumerate(vs) for b in vs[i + 1:]]
    return CSP(vs, {v: list(range(holes)) for v in vs}, edges)


def ring(n, col):
    vs = ["r%d" % i for i in range(n)]
    return CSP(vs, {v: list(range(col)) for v in vs},
               [(vs[i], vs[(i + 1) % n]) for i in range(n)])


def tree12(col):
    """12 nodes: path t0..t7, leaves t8,t9 on t3, leaves t10,t11 on t6. 11 edges."""
    vs = ["t%d" % i for i in range(12)]
    edges = [(vs[i], vs[i + 1]) for i in range(7)]
    edges += [(vs[3], "t8"), (vs[3], "t9"), (vs[6], "t10"), (vs[6], "t11")]
    return CSP(vs, {v: list(range(col)) for v in vs}, edges)


def ac3(csp, dom):
    """Queue-based arc consistency (AIMA REVISE + queue). Returns (ok, arcs, pruned)."""
    q = deque((a, b) for a in csp.vars for b in csp.nb[a])
    arcs = pruned = 0
    while q:
        xi, xj = q.popleft()
        arcs += 1
        keep = [x for x in dom[xi] if any(csp.ok(xi, x, xj, y) for y in dom[xj])]
        if len(keep) != len(dom[xi]):
            pruned += len(dom[xi]) - len(keep)
            dom[xi] = keep
            if not keep:
                return False, arcs, pruned
            q.extend((xk, xi) for xk in csp.nb[xi] if xk != xj)
    return True, arcs, pruned


def backtrack(csp, mode="plain"):
    """Depth-first assignment. mode: plain | fc | mac. The counters are the evidence."""
    vs = list(csp.vars)
    dom = {v: list(csp.dom0[v]) for v in csp.vars}
    st = {"tried": 0, "rollbacks": 0}
    assign = {}

    def bt():
        if len(assign) == len(vs):
            return True
        v = next(u for u in vs if u not in assign)
        for x in list(dom[v]):
            if any(u in assign and not csp.ok(v, x, u, assign[u]) for u in csp.nb[v]):
                continue
            st["tried"] += 1
            snap = {u: list(d) for u, d in dom.items()}
            assign[v] = x
            dom[v] = [x]
            good = True
            for u in csp.nb[v]:
                if u in assign:
                    continue
                if mode in ("fc", "mac"):
                    keep = [y for y in dom[u] if csp.ok(u, y, v, x)]
                    dom[u] = keep
                    if not keep:
                        good = False
                        break
            if good and mode == "mac":
                good, _, _ = ac3(csp, dom)
            if good and bt():
                return True
            dom.clear()
            dom.update({u: list(d) for u, d in snap.items()})
            del assign[v]
            st["rollbacks"] += 1
        return False

    bt()
    return st


def brute_solutions(csp):
    """Only for small instances: full enumeration, no cleverness."""
    total = 1
    for v in csp.vars:
        total *= len(csp.dom0[v])
    n = 0
    for code in range(total):
        pick, rest = {}, code
        for v in csp.vars:
            d = csp.dom0[v]
            pick[v] = d[rest % len(d)]
            rest //= len(d)
        if all(pick[a] != pick[b] for a in csp.vars for b in csp.nb[a] if a < b):
            n += 1
    return n, total


def is_tree(csp):
    """Connected and exactly |V| - 1 undirected edges -- the test from the lab."""
    edges = {tuple(sorted((a, b))) for a in csp.vars for b in csp.nb[a] if a != b}
    if len(edges) != len(csp.vars) - 1:
        return False
    seen = {csp.vars[0]}
    q = deque([csp.vars[0]])
    while q:
        u = q.popleft()
        for w in csp.nb[u]:
            if w not in seen:
                seen.add(w)
                q.append(w)
    return len(seen) == len(csp.vars)


def solve_tree(csp):
    """Tree theorem: one AC-3 call, then one downward walk. No search at all.

    On a tree, AC-3 is complete: it either empties a domain (unsatisfiable) or
    makes every value of a node supported by a value of each neighbour, so the
    child always still holds a value that agrees with the parent's choice.
    """
    dom = {v: list(csp.dom0[v]) for v in csp.vars}
    ok, arcs, pruned = ac3(csp, dom)
    if not ok:
        return None, pruned, arcs, 0
    root = csp.vars[0]
    parent, order = {root: None}, []
    q = deque([root])
    while q:
        u = q.popleft()
        order.append(u)
        for w in csp.nb[u]:
            if w not in parent:
                parent[w] = u
                q.append(w)
    assign = {root: dom[root][0]}
    steps = 1
    for u in order[1:]:
        p = parent[u]
        assign[u] = next(x for x in dom[u] if csp.ok(u, x, p, assign[p]))
        steps += 1
    return assign, pruned, arcs, steps


def min_conflicts(csp, steps=2000, seed=34, walk=0.2):
    """Repair-based local search, with the escape move the slides ask for."""
    rng = random.Random(seed)
    val = {v: rng.choice(csp.dom0[v]) for v in csp.vars}

    def bad(v):
        return sum(1 for u in csp.nb[v] if val[u] == val[v])

    for s in range(1, steps + 1):
        broken = [v for v in csp.vars if bad(v)]
        if not broken:
            return s - 1, 0, True
        v = rng.choice(broken)
        if rng.random() < walk:
            val[v] = rng.choice(csp.dom0[v])
        else:
            val[v] = min(csp.dom0[v], key=lambda x: sum(1 for u in csp.nb[v] if val[u] == x))
    return steps, sum(1 for v in csp.vars if bad(v)), False

A column of zeros, three times, on instances with no solution at all: 4 pigeons into 3 holes, 5 into

4, and a 9-node cycle with 2 colours. AC-3 revised 12, 20 and 18 arcs, found support for every single

value, and returned success. The brute-force column is the truth: 0, 0, 0.

The pair worth reading twice is rows three and four. C8 and C9 end with the identical domains —

{0,1} on every variable, not one value removed — and one has 2 solutions while the other has 0.

Any check that reads only the output of AC-3 cannot tell an even cycle from an odd one. Not "does not

usually": cannot. The information is not in the domains. The proof is three lines long: on a

2-coloured cycle every value is supported by the neighbour on either side, and the parity only

becomes a contradiction when the last assignment closes the loop — which is exactly the structure

support checking does not see.

So the certificate is worthless where it is needed most, and the next question is what the truth

costs. Two things surprised me:

  • Forward checking is identical to plain backtracking here, to the digit — 64 and 64 on the

pigeonhole instance, 16 and 16 on the odd cycle. On a complete graph with a single "different

value" constraint, FC's pruning removes precisely the values the consistency check would have

rejected one step later, so it does the same work under a different name. FC earns its keep when

the constraint is tighter than the domain; here it is not.

  • MAC is not FC with a new label. It is the same AC-3, called after each assignment instead of

once at the start, and that is where the attempts went: 64 → 40, and 16 → 2. Static AC-3 pruned

nothing; AC-3 maintained during the search pruned the whole branch in two nodes.

That is the lesson of the week, and it is the opposite of what I assumed: the strength was never in

AC-3's output, it was in when AC-3 runs.

The third lever changes the asymptotics. A 12-node tree, 3 colours: AC-3 finishes arc-consistent

having pruned nothing (a tree is always 2-colourable under a "different value" constraint, so there

is nothing to prune), and then the assignment is a walk — root takes its first value, each node

downward picks a value that agrees with its parent. 12 assignments, 0 rollbacks, and next(...)

never raised, because arc consistency on a tree means every value of a parent is supported by a

value that survives in the child, so the child can always follow. No choice points to undo.

The same call on an unsatisfiable tree gives a verdict with zero search: hub on {0,1}, two

leaves pinned at 0 and 1, a third free. AC-3 empties the hub after 2 arcs, 0 value attempts. On a

tree arc consistency is complete; on the 9-cycle it was not; the difference between those two graphs

is one cycle. That is why "ring minus one node" — a path of 8, is_tree=True — is the standard

repair for almost-a-tree: cut the cycle, enumerate the cut variable, and every branch is a tree you

solve without search. Ring C9 has treewidth 2; the pigeonhole instance is a complete graph, treewidth

n−1, and no decomposition will save it. That is the honest boundary of this lever.

Min-conflicts is the fourth lever and the only one with no guarantee. Start complete, pick a

conflicted variable, move it to the value with the fewest conflicts. On C8, where 2 solutions exist

out of 256, a purely greedy run ended after 2000 steps with 4 conflicts and no solution — the plateau

where every move leaves the count identical. Adding the escape move the slides ask for (a 20% chance

of picking a random value) solved it in 49 steps. On C9 there is nothing to find and it never

converged: 2000 steps, 2 conflicts left. Fast, memory-light, and unable to prove a negative — the

exact trade against backtracking.

What I understood from it: arc consistency is a statement about pairs; satisfiability is a

statement about the whole graph. On trees the two coincide — that is a theorem, not a habit, and it

is why acyclic structure is worth hunting for. Everywhere else AC-3 buys pruning and nothing more,

and the honest way to measure a pruner is not how many values it deletes at the start but how much

search it deletes while the search is running. This morning I had those two backwards.

Security #34 — The upload that is 2,694 bytes and declares four gigabytes

CWE-409, decompression bomb. The defect is not a memory-safety bug; it is a number the receiver

agrees to trust. A zip's central directory states, for every member, how many bytes it will produce.

Zeros compress to about a thousandth of their size, so 2.7 KB of nested archives can declare four

gigabytes — and the declaration is not a lie, which is what makes it work: an extractor that honours

it writes all four gigabytes.

What survives the usual checks is nesting. A single archive with a 1000:1 ratio is easy to flag. Four

levels of four members each: the file an upload endpoint sees is 2,694 bytes, its top level declares

8,584 bytes across 4 members — a ratio of 3:1 that passes any plausible limit, because the

compression only shows up at the bottom.

The pattern I studied: a recursive extractor that carries no counter — every member's declared

size is read, trusted, and turned into writes.

def make_zip(entries):
    """Fixed timestamps and attributes: the same entries must give the same bytes."""
    buf = io.BytesIO()
    with zipfile.ZipFile(buf, "w", zipfile.ZIP_DEFLATED) as z:
        for name, data in entries:
            zi = zipfile.ZipInfo(name, date_time=(2026, 11, 10, 0, 0, 0))
            zi.compress_type = zipfile.ZIP_DEFLATED
            zi.external_attr = 0o600 << 16
            z.writestr(zi, data, compress_type=zipfile.ZIP_DEFLATED, compresslevel=9)
    return buf.getvalue()

def declared_total(zbytes, depth=0):
    """Read central directories only. Inflates inner zips, never a payload."""
    z = zipfile.ZipFile(io.BytesIO(zbytes))
    total = files = deepest = 0
    for info in z.infolist():
        if info.filename.lower().endswith(".zip"):
            inner_bytes, inner_files, inner_depth = declared_total(z.read(info), depth + 1)
            total += inner_bytes
            files += inner_files
            deepest = max(deepest, inner_depth)
        else:
            total += info.file_size
            files += 1
            deepest = max(deepest, depth)
    return total, files, deepest

def inflate_all(zbytes, budget=None):
    """What an extractor with no limit would write. Output is discarded, only counted."""
    z = zipfile.ZipFile(io.BytesIO(zbytes))
    nbytes = nfiles = 0
    for info in z.infolist():
        if info.filename.lower().endswith(".zip"):
            b, f, stopped = inflate_all(z.read(info), budget)
            nbytes += b
            nfiles += f
            if stopped:
                return nbytes, nfiles, True
        else:
            with z.open(info) as fh:
                while True:
                    chunk = fh.read(1 << 20)
                    if not chunk:
                        break
                    nbytes += len(chunk)
                    if budget is not None and nbytes >= budget:
                        return nbytes, nfiles + 1, True
            nfiles += 1
    return nbytes, nfiles, False

      % (written, written / (1024 ** 3), files_written))
print("  the headers were honest. nothing here is a guess.")


def guarded_extract(zbytes, budget=BUDGET, maxfiles=MAXFILES):
    """Audit first: cost is the size of the archive, not the size of the bomb."""
    try:
        total, files, _ = declared_total(zbytes)
    except (zipfile.BadZipFile, OSError):
        return "reject", "unreadable archive", 0
    if total > budget:
        return "reject", "%d B declared > %d B budget" % (total, budget), 0
    if files > maxfiles:
        return "reject", "%d files > %d" % (files, maxfiles), 0
    n = 0
    z = zipfile.ZipFile(io.BytesIO(zbytes))
    for info in z.infolist():
        with z.open(info) as fh:
            while True:
                chunk = fh.read(1 << 20)
                if not chunk:
                    break
                n += len(chunk)
                if n > budget:          # the header can lie; the byte count cannot
                    return "reject", "stream exceeded budget at %d B" % n, n
    return "accept", "total %d B" % n, n

fails: 3:1 at the top, 3:1 at level two, and the 1022:1 that gives the game away only appears at

level four, which no top-level size or ratio check ever opens.

The second measurement is the one that changed how I think about the class. Sizes in a zip are written

by whoever built the zip. A 1,147-byte archive whose central directory says 100 bytes: the reader that

trusts the header — which is what the standard library does — returns 100 bytes, the CRC passes, no

error. A reader that inflates the compressed stream gets 1,048,576 bytes out of the same member. Two

readers, one file, 10,485 times apart. "Check the declared size before extracting" is therefore not a

defence: it is asking the attacker how big their file is.

What I understood about preventing it: audit the whole tree before touching it — declared total,

file count, depth, and a cap on the depth — because the audit costs the size of the archive (2,694

bytes here) while the extraction costs what the archive claims. Then, because the header can lie,

count the bytes as they come out, with one cumulative budget across the whole tree instead of a budget

per file.

def guarded_extract(zbytes, budget=BUDGET, maxfiles=MAXFILES):
    """Audit first: cost is the size of the archive, not the size of the bomb."""
    try:
        total, files, _ = declared_total(zbytes)
    except (zipfile.BadZipFile, OSError):
        return "reject", "unreadable archive", 0
    if total > budget:
        return "reject", "%d B declared > %d B budget" % (total, budget), 0
    if files > maxfiles:
        return "reject", "%d files > %d" % (files, maxfiles), 0
    n = 0
    z = zipfile.ZipFile(io.BytesIO(zbytes))
    for info in z.infolist():
        with z.open(info) as fh:
            while True:
                chunk = fh.read(1 << 20)
                if not chunk:
                    break
                n += len(chunk)
                if n > budget:          # the header can lie; the byte count cannot
                    return "reject", "stream exceeded budget at %d B" % n, n

Measured: the audit refused the bomb with 0 payload bytes inflated and 0 files written; the running

cap alone stopped at 67,108,864 bytes after 4 files — a quarter of one percent of the payload, and

already 4 files on disk. The same guard accepted a normal 1,920,000-byte archive.

The limits of what I built, honestly: my audit inflates the inner zips to read their directories, so

it is bounded by the compressed size of the archive, not by nothing — a 2.7 KB bomb is cheap to

audit, a 200 MB bomb of bombs is not. And a byte cap stops the inflation, not the extractor: whatever

it already wrote is on disk, which is why the extraction directory needs to be disposable and

quota-limited, not just the stream watched.
